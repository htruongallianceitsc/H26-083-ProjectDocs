# Prompt 32 — Request Capture and Promotion

Given a new project request:

1. Decide whether it is durable enough to capture as a Request.
2. Capture the request before changing canonical scope when provenance matters.
3. Analyze which canonical entities must be created or changed.
4. Update Feature/Requirement/Rule/Screen/API/DB/Test/Decision documents first.
5. Run validation.
6. Promote the Request only to entities that now exist.
7. Never treat the Request note as the final specification.
