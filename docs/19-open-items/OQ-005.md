# Open Question

## Question
Which transactional email provider should back `INT-EMAIL`, and should a broader in-app/email notification system (for comments, assignments, due dates) be built in the near term?

## Why It Matters
Password reset and workspace invite emails are in v1 scope and need a concrete provider before release; broader notifications are out of scope but frequently requested in Trello-like tools.

## Options / Evidence
Provider choice is an implementation detail deferred to the engineering team closer to release; broader notifications deferred per `docs/00-project/product-scope.md`.

Blocking for release: `INT-EMAIL` provider must be selected before `FEAT-AUTH-FORGOT-PASSWORD` and `FEAT-WORKSPACE-MANAGE-MEMBERS` can ship to production. Not blocking for the broader notification system, which remains deferred.
