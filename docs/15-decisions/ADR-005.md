# Architecture / Product Decision Record

## Context
Users need a way to remove Boards/Lists/Cards/Comments from active view without risking accidental permanent data loss, and the system benefits from retaining history for the activity log and future analytics.

## Decision
Boards, Lists, and Cards use an `archived_at` soft-delete column; Comments use `deleted_at`. No end-user-facing hard-delete endpoint exists for these entities in v1.

## Options Considered
- **Soft delete (chosen)** — reversible, preserves `activity_log` referential integrity, matches Trello's own "archive" mental model.
- **Hard delete** — simpler schema, but destructive and irreversible; would orphan `activity_log` entries referencing deleted cards.

## Rationale
Archiving matches the product's mental model (explicitly requested Trello-like behavior) and avoids irreversible data loss from a misclick.

## Consequences
Every list/card query in the system filters `archived_at IS NULL` by default (see `DB-BOARD`, `DB-LIST`, `DB-CARD`, `DB-COMMENT` docs). A restore/unarchive UI for Cards specifically is not yet built (see `FEAT-CARD-ARCHIVE` known limitations) — this is the main near-term gap this decision creates.

## Risks
Without a restore UI, an accidentally archived card is currently only recoverable via direct database action; tracked as a near-term follow-up, not a blocking open question.

## Affected Entities
`DB-BOARD`, `DB-LIST`, `DB-CARD`, `DB-COMMENT`.

Accepted
