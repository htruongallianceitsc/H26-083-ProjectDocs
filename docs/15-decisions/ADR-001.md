# Architecture / Product Decision Record

## Context
KanbanFlow needs a single, reliable relational store for Workspaces, Boards, Lists, Cards, and their relationships, with strong consistency for the drag-and-drop move operation.

## Decision
Use PostgreSQL 15+ as the sole primary datastore.

## Options Considered
- **PostgreSQL** — mature, strong transactional guarantees, JSONB support for `activity_log.metadata`, widely supported by managed hosting.
- **MySQL** — viable alternative, weaker JSON/constraint ergonomics for this use case.
- **MongoDB** — document model doesn't map cleanly to the highly relational Board/List/Card/Label/Member graph; would complicate the fractional-ordering and cascade-delete logic.

## Rationale
The domain is inherently relational (foreign keys, cascades, unique constraints are used extensively — see `docs/08-database/`), and the move/reorder operations need transactional guarantees that a relational engine provides naturally.

## Consequences
All schema design follows `docs/08-database/database-overview.md` conventions (UUID PKs, audit columns, soft-delete via `archived_at`). Technology stack selection (`nodejs-api` + `postgresql`) reflects this.

## Risks
None significant at MVP scale; revisit read-replica/sharding needs if usage grows well beyond `NFR-SCALE-001` targets.

## Affected Entities
All `DB-*` database objects.

Accepted
