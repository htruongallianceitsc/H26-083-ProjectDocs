Workflow 16 — Progressive Specification / Lightweight Mode

Goal

Choose documentation depth intentionally, avoid over-documenting mock/POC work, and preserve a deterministic promotion path to Standard or Full.

Steps

  • Resolve project default from project.profile.json.documentation.defaultSpecLevel.
  • For each Feature, decide whether an override is needed.
  • Run recommendation when risk/maturity is unclear:

```bash

cd tools

npm run spec:recommend -- --feature FEAT-...

```

  • Author the Feature using the selected depth. Use kit/templates/lightweight-feature-template.md for Lightweight.
  • Check the selected profile:

```bash

npm run spec:check -- --feature FEAT-...

npm run gate:ready -- --feature FEAT-...

```

  • Before moving to a higher delivery maturity, generate a promotion gap report:

```bash

npm run spec:promote -- --feature FEAT-... --to standard

```

  • Create only the missing canonical entities/contracts supported by confirmed knowledge.
  • Re-run the promotion report; apply only when no target-level gaps remain.
  • Update PROJECT_BLUEPRINT.md with current spec level and maturity.

Exit criteria

  • Effective spec level is explicit and appropriate for current maturity.
  • Risk recommendation is reviewed.
  • Current Ready gate passes for the chosen level.
  • Promotion gaps are visible before UAT/production hardening.
