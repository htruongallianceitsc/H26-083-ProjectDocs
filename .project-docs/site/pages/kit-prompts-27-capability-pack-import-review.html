Prompt 27 — Review Capability Pack Import

Review a capability-pack import preview before it is applied.

Check:

  • selected required/optional features match project scope;
  • variable values are appropriate for project type/technology stack;
  • code namespace and target root do not collide;
  • no project-specific business/security rule is being accepted blindly;
  • required integrations/dependencies exist or become Open Questions;
  • imported ADR/default assumptions are acceptable;
  • disabled feature relations are pruned;
  • resulting Feature -> Requirement/Screen/API/Test traceability is coherent;
  • imported files should become local canonical docs;
  • pack lock contains provenance only, not secrets/business facts.

Output:

  • approve/revise import plan;
  • variable changes required;
  • optional features to enable/disable;
  • Open Questions/ADRs to create after import;
  • validation commands to run.
