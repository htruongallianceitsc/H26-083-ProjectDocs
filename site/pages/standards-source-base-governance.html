Source Base Governance

A Source Base is a versioned bootstrap skeleton, not a continuously linked dependency.

  • Select a Source Profile.
  • Materialize a Source Base variant with source:init.
  • Record provenance in .project-docs/source.lock.json.
  • Treat the copied application source as canonical after initialization.
  • Never auto-overwrite project source from a newer Source Base.
  • Use source:upgrade-check to discover a newer base and create a reviewed migration WorkPlan if an upgrade is wanted.
  • Business/domain features belong in project docs or Capability Packs, not in generic Source Bases.
  • Keep Source Bases free of dependency caches, secrets, build output and generated binaries.
